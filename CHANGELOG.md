# Changelog

Все значимые изменения проекта документируются в этом файле.

## [Unreleased]

## [0.1.4] - 2026-10-13

### Added

- README: переводы на EN / ES (`README.en.md`, `README.es.md`) со свитчером
  языка и секцией «Ресурсы» (ссылки на бот @make_my_shop_bot и сайт
  needl3.net)
- Чат клиента с менеджером по заказу: кнопка «💬 Написать менеджеру» в
  карточке заказа клиента открывает экран переписки — та же история, что у
  администратора (пагинация по 5 сообщений, открытие с последней страницы),
  плюс ввод ответа. Отдельный чат на каждый заказ (`Order.chat_history`);
  ответ клиента сохраняется в историю и администраторы получают уведомление
- Защита чата: для отменённых (cancelled) заказов чат закрыт — кнопка
  «Написать менеджеру» скрывается в карточке заказа и в сообщении от админа,
  нажатие старой кнопки даёт alert «Чат по этому заказу закрыт»
- Приём только текстовых сообщений в чате заказа (клиент и админ):
  фото/стикеры/голосовые не сохраняются в историю, показывается подсказка
- Сброс FSM-состояния ввода ответа при уходе из чата по навигации
  («Назад к списку», пагинация списка, «Посмотреть заказ») — следующий текст
  клиента больше не принимается за ответ по заказу
- Общий сервис `services/chat_service.py` (`format_chat_history` с
  параметризованным callback-префиксом) — единая логика рендера истории
  для админского и клиентского хендлеров
- Тесты: `tests/test_chat_service.py` (пагинация, префиксы, клампинг) и
  `tests/test_client_order_chat.py` (кнопка карточки, закрытый чат для
  cancelled, чужой заказ, не-текст, сохранение, уведомление админа, сброс FSM)

### Changed

- Время сообщений в истории чата заказа записывается в UTC
  (`datetime.now(timezone.utc)` вместо deprecated `datetime.utcnow()`)
- Смена языка клиентом редактирует главное меню на месте (edit in place)
  вместо «удалить + отправить» — убирает мигание сообщения

### Fixed

- Аудит «одного сообщения»: ввод админа больше не остаётся в чате в ветках
  ошибок — удаляется до показа подсказки:
  - `catalog.py`: неверное название категории (валидация)
  - `welcome_editor.py`: слишком длинный текст приветствия (валидация)
  - `welcome_editor.py`: прислан не фото (неверный ввод)
  - `contact.py`: не-текстовое сообщение админа в состоянии «написать клиенту»
- `catalog.py`: блокирующий `await self_destruct(..., seconds=3)` заменён на
  `asyncio.create_task(...)` — хэндлер не ждёт 3 секунды
- `order_payment_request.py`: «edit + sleep(3) + delete» временного сообщения
  вынесен в `asyncio.create_task(_edit_and_delete_later(...))` — подтверждение
  и отклонение оплаты не блокируют хэндлер
- `render_product.py`: удалён мёртвый дубликат хелпера `self_destruct`
  (и неиспользуемые импорты `asyncio` / `TelegramBadRequest` / `Message`)
- `contact.py`: не импортировался `MESSAGES_PER_PAGE` (использовался при
  расчёте стартовой страницы чата) — падение при runtime исправлено
- Тесты: `tests/test_admin_input_cleanup.py` — проверка удаления ввода админа
  в каждой из исправленных веток ошибок
- Карточка заказа: при фото-чеке (caption под фото) разделитель блоков
  переносился на две строки — для caption используется короткий разделитель
  (12 `━` вместо 20), обычный текст сообщения не меняется
  (`order_service.py` + шаблон `detail_card` в `locale.json`)
- Тесты: `tests/test_order_detail_separator.py` — длина разделителя в
  зависимости от типа чека
- Бейдж корзины в главном меню показывал устаревшее количество после
  отправки заказа: `get_user_with_cart` читал устаревшую cart-коллекцию из
  identity map (сессия с `expire_on_commit=False`, без `populate_existing`),
  хотя корзина уже очищена в БД. Теперь `get_user_with_cart` перечитывает
  корзину/заказы из БД (`populate_existing=True` в `get_by_id`); добавлен
  регрессионный тест `test_cart_badge_reset_after_order`

## [0.1.3] - 2026-09-26

### Added

- Уведомление администраторов о новом заказе: при оформлении заказа
  (`checkout_confirm`) каждому админу в фоне (не блокируя ответ клиенту)
  отправляется карточка заказа с кнопкой «📋 Перейти к заказу»
  (callback `admin_order_view:{order_id}`, открывает существующий
  админ-хендлер просмотра заказа). Уведомление на языке каждого админа
  (EN — по умолчанию); ошибка отправки одному админу логируется и не
  блокирует остальных
- Меню команд бота (`/` в чате):
  - `/start` — глобально для всех пользователей (выставляется при старте
    бота)
  - `/admin` — только для администраторов, через per-chat scope
    (`BotCommandScopeChat`); выставляется в `DbSessionMiddleware` с
    in-memory кэшем (повторные API-вызовы не дёргаются; смена языка или
    прав админа — команды переставляются)
- Тесты: `tests/test_new_order_notification.py` (язык админа, кнопка
  заказа, изоляция ошибок, отсутствие заказа) и `tests/test_bot_commands.py`
  (состав команд, per-chat scope, кэш, middleware)

## [0.1.2] - 2026-09-12

### Changed

- Дефолтный язык интерфейса теперь `en` (был `ru`); фолбэк при отсутствии
  перевода всегда на `en`
- Удалена настройка `NOTIFICATIONS_LANG`: уведомления администраторам
  (оплата, отмена) теперь отправляются на языке каждого администратора
  (из БД)
- Новый пользователь создаётся с `language=None`: при первом `/start`
  показывается выбор языка, после выбора язык сохраняется в БД
- Кнопка «Менеджер» в карточке товара настраивается переменной окружения
  `MANAGER_URL`; если не задана — кнопка скрывается (ранее URL был
  захардкожен)

### Fixed

- `IsAdminFilter`: сигнатура `__call__` теперь принимает `admin_ids`
  напрямую (kwarg из workflow data), а не `data: Dict`. aiogram 3 передаёт
  workflow data поимённо и ключ `data` не содержит → на любом сообщении
  (включая клиентские) возникал `TypeError`, т.к. root-фильтр админ-роутера
  проверяется для всех событий. Добавлены регрессионные тесты
  (`tests/test_admin_filter.py`).
- Packaging `shopcrm-core`: `locales/locale.json` теперь включается в wheel
  (`[tool.setuptools.package-data]`). Ранее файл не попадал в установленный
  пакет, из-за чего `Locale` молча падал на пустой словарь и обработчик
  ошибок бота крешил с `FileNotFoundError`

## [0.1.1] - 2026-09-11

### Changed

- Администраторы теперь передаются через workflow data (`admin_ids`):
  `DbSessionMiddleware` принимает опциональный параметр `admin_ids`
  (нужен для мульти-тенантового хостинга). Self-hosted поведение не
  изменилось — по умолчанию используется `config.ADMIN_ID`
- `IsAdminFilter`, уведомления об оплате/отмене и ответ клиента
  администратору используют инжектированные `admin_ids`
  (фолбэк на `config.ADMIN_ID`)

## [0.1.0] - 2026-09-07

### Added

- Каталог товаров с категориями и поиском
- Корзина: добавление, изменение количества, удаление
- Оформление заказа: адрес доставки, комментарий, расчёт итога
- Оплата: прикрепление чека (фото / текст), подтверждение администратором
- История заказов со статусами и чатом с поддержкой
- Админ-панель: CRUD товаров и категорий, управление статусами заказов
- Мультиязычность (RU / EN) с переключением в боте
- Настройки через `.env` (pydantic-settings)
- Асинхронная БД (SQLAlchemy 2.0 + asyncpg / aiosqlite)
- Миграции (Alembic)
- Тестовый набор: 44 теста (расчёты, ownership, локализация, конфиг)
