# Changelog

Все значимые изменения проекта документируются в этом файле.

## [0.1.8] - 2026-11-13

### Added

- Админ-панель: раздел «Юзеры» — список пользователей с циклической
  пагинацией (5 на страницу) и поиск по ID
- Карточка пользователя: имя, @username, дата регистрации, язык,
  роль, статус (активен/неактивен), количество заказов, потрачено
  (без отменённых заказов), текущая скидка
- Персональная скидка (0–100, дробные значения, поддерживается
  запятая) — устанавливается из карточки пользователя, хранится в
  поле `users.discount`
- Миграция: `add_user_discount`
- Тесты: `tests/test_users_list.py` (список, поиск, карточка,
  валидация скидки, репозиторий, сервис, FSM-поток)

### Changed

- Чистка мёртвого кода: удалён пустой файл `keyboards/common.py` и
  закомментированные хэндлеры в админ-панели

## [0.1.7] - 2026-11-08

### Added

- Аудит заказов: журнал смены статусов (`order_status_history`) — каждая
  смена статуса фиксируется (кто, когда, из чего в что). Записи
  неизменяемы; старые очищаются по политике хранения
- Аудит заказов: поля `paid_at`/`paid_by` (когда и кем отмечен как
  оплаченный), `completed_at`, `cancelled_at`, `updated_at`
- Политика хранения журнала статусов: `AUDIT_RETENTION_DAYS` (по
  умолчанию 180 дней; `<= 0` отключает очистку). Очистка выполняется
  автоматически при старте бота и далее раз в сутки
- Профиль клиента: имя и username из Telegram (`first_name`, `username`)
  и дата первого обращения (`created_at`) — для отчётов и карточек
- Склад: поле комментария к движению (`stock_movements.comment`) —
  заделка под будущее: колонка, сервис и репозиторий готовы; ввод
  комментария из интерфейса — в планах
- Аудит каталога: у товаров и категорий — `created_at`, `updated_at`,
  `updated_by` (кто последний раз изменял)
- Настройки магазина: таблица `settings` (ключ-значение) для настроек,
  которые администратор меняет в процессе работы
- Миграции: `add_order_audit_fields`, `add_user_profile_fields`,
  `add_stock_movement_comment`, `add_product_category_audit_fields`,
  `add_settings_table`
- Тесты: `tests/test_retention.py` (политика хранения) и
  `tests/test_order_audit.py` (журнал смены статусов, поля аудита)

### Fixed

- Аудит заказов: `paid_at`/`completed_at`/`cancelled_at` записывались как
  aware-даты (`datetime.now(UTC)`) в колонки
  `TIMESTAMP WITHOUT TIME ZONE` — на PostgreSQL (asyncpg) смена статуса
  заказа падала с ошибкой
  `can't subtract offset-naive and offset-aware datetimes`. Теперь
  записывается naive UTC (та же конвенция, что в остальном core)
- Склад: управление остатками товаров — физический остаток (`stock`),
  бронирование под активные заказы (`reserved`) и накопительные метрики
  (`total_arrived`, `total_written_off`, `total_sold`)
- Админ-панель: раздел «Склад» — пополнение остатка, списание, просмотр
  остатков по категориям
- Видимость товара для клиента учитывает остаток: товар показывается,
  если активен и доступно (`stock - reserved`) больше 0
- Лимит корзины: нельзя заказать больше доступного остатка
- Жизненный цикл остатка привязан к заказу: бронирование при создании,
  разблокировка при отмене, списание со склада при завершении
- Миграции: `add_stock_to_products`, `add_stock_metrics_to_products`,
  `add_stock_movements`
- Тесты: `tests/test_warehouse.py` (видимость, лимиты корзины,
  пополнение/списание, валидация количества, журнал движений)
- Журнал складских движений (`stock_movements`): каждое пополнение,
  списание, бронирование, снятие брони и списание по завершённому
  заказу фиксируется в той же транзакции, что и обновление балансов —
  с фактическим количеством, снимками остатков (`stock_after`,
  `reserved_after`), ссылкой на заказ и администратора. Основа для
  будущей статистики и аудита склада
- Склад: полное удаление товара (кнопка «🗑 Удалить» в карточке товара
  с подтверждением) — необратимо стирает товар, его журнал движений и
  локали. Блокируется, пока есть остаток (`stock > 0`) или активные
  заказы (`reserved > 0`); ID администратора фиксируется в логе
- Склад: возврат архивного товара в каталог (кнопка «♻️ Восстановить» в
  карточке архивного товара) — устанавливает `is_active=True`: товар снова
  виден в магазине и попадает в черновик каталога при следующем открытии
  редактора. Остаток, журнал движений и заказы не затрагиваются; ID
  администратора фиксируется в логе
- Тесты: архивация при публикации каталога, пропуск архивных товаров в
  черновике, блокировки и успех полного удаления, возврат из архива
  (`tests/test_warehouse.py`)

### Changed

- Смена статуса заказа (администратором и клиентом) теперь фиксируется в
  журнале аудита; отмена клиентом — с причиной. Поля аудита
  (`paid_at`/`paid_by`, `completed_at`, `cancelled_at`) выставляются
  автоматически при соответствующих переходах
- Удаление товара из каталога теперь **архивирует** товар
  (`is_active=False`), а не удаляет строку: остатки, журнал движений,
  локали и ссылки в заказах сохраняются — статистику не теряем. Товар
  скрывается из каталога и магазина, но остаётся на складе с пометкой 🗄.
  Полное удаление — только вручную из раздела «Склад»
- Черновик каталога (`sync_to_temp`) копирует только активные товары:
  архивные не показываются в редакторе и не «оживают» при публикации.
  Возврат в каталог — кнопкой «♻️ Восстановить» на складе

### Fixed

- Миграции: переносимость между SQLite и PostgreSQL — добавление колонок
  и индексов через `op.batch_alter_table` (SQLite требует пересоздания
  таблицы). Проверено: upgrade/downgrade на чистой БД и на БД с данными

## [0.1.6] - 2026-11-01

### Added

- 4 новых статуса заказа: «❌ Платёж не подтверждён» (`payment_rejected`),
  «📦 Готов к выдаче» (`ready_for_pickup`), «⏸ На паузе» (`on_hold`),
  «💸 Возврат в процессе» (`refund_in_progress`) — в меню фильтров, меню
  смены статуса и карточке клиента; клиент может отменить заказ до передачи
  курьеру

### Changed

- Статусы заказа показываются локализованными подписями (ru/en/es) во всех
  точках: список администратора (заголовок, строки, кнопки), карточка
  заказа, alert после смены статуса
- Формат цен: минимум 2 знака после точки (`10` → `10.00`), единый
  `format_price` во всех точках отображения (каталог, корзина, карточка
  заказа, список заказов, экспорт CSV)
- Карточка заказа администратора: 4 блока (дата/статус/комментарий
  менеджера | покупатель/адрес/комментарий клиента/оплата | состав |
  расчёт стоимости); покупатель — ID со ссылкой `tg://user?id=…`
- Пустые поля карточки заказа — единый плейсхолдер «Пусто» / «empty» /
  «vacío»

## [0.1.4] - 2026-10-13

### Added

- README: переводы на EN / ES (`README.en.md`, `README.es.md`) со свитчером
  языка и секцией «Ресурсы» (ссылки на бот @make_my_shop_bot и сайт
  needl3.net)
- Чат клиента с менеджером по заказу: кнопка «💬 Написать менеджеру» в
  карточке заказа клиента открывает экран переписки — та же история, что у
  администратора (пагинация по 5 сообщений, открытие с последней страницы),
  плюс ввод ответа. Отдельный чат на каждый заказ (`Order.chat_history`);
  ответ клиента сохраняется в историю и администраторы получают уведомление
- Защита чата: для отменённых (cancelled) заказов чат закрыт — кнопка
  «Написать менеджеру» скрывается в карточке заказа и в сообщении от админа,
  нажатие старой кнопки даёт alert «Чат по этому заказу закрыт»
- Приём только текстовых сообщений в чате заказа (клиент и админ):
  фото/стикеры/голосовые не сохраняются в историю, показывается подсказка
- Сброс FSM-состояния ввода ответа при уходе из чата по навигации
  («Назад к списку», пагинация списка, «Посмотреть заказ») — следующий текст
  клиента больше не принимается за ответ по заказу
- Общий сервис `services/chat_service.py` (`format_chat_history` с
  параметризованным callback-префиксом) — единая логика рендера истории
  для админского и клиентского хендлеров
- Тесты: `tests/test_chat_service.py` (пагинация, префиксы, клампинг) и
  `tests/test_client_order_chat.py` (кнопка карточки, закрытый чат для
  cancelled, чужой заказ, не-текст, сохранение, уведомление админа, сброс FSM)

### Changed

- Время сообщений в истории чата заказа записывается в UTC
  (`datetime.now(timezone.utc)` вместо deprecated `datetime.utcnow()`)
- Смена языка клиентом редактирует главное меню на месте (edit in place)
  вместо «удалить + отправить» — убирает мигание сообщения

### Fixed

- Аудит «одного сообщения»: ввод админа больше не остаётся в чате в ветках
  ошибок — удаляется до показа подсказки:
  - `catalog.py`: неверное название категории (валидация)
  - `welcome_editor.py`: слишком длинный текст приветствия (валидация)
  - `welcome_editor.py`: прислан не фото (неверный ввод)
  - `contact.py`: не-текстовое сообщение админа в состоянии «написать клиенту»
- `catalog.py`: блокирующий `await self_destruct(..., seconds=3)` заменён на
  `asyncio.create_task(...)` — хэндлер не ждёт 3 секунды
- `order_payment_request.py`: «edit + sleep(3) + delete» временного сообщения
  вынесен в `asyncio.create_task(_edit_and_delete_later(...))` — подтверждение
  и отклонение оплаты не блокируют хэндлер
- `render_product.py`: удалён мёртвый дубликат хелпера `self_destruct`
  (и неиспользуемые импорты `asyncio` / `TelegramBadRequest` / `Message`)
- `contact.py`: не импортировался `MESSAGES_PER_PAGE` (использовался при
  расчёте стартовой страницы чата) — падение при runtime исправлено
- Тесты: `tests/test_admin_input_cleanup.py` — проверка удаления ввода админа
  в каждой из исправленных веток ошибок
- Карточка заказа: при фото-чеке (caption под фото) разделитель блоков
  переносился на две строки — для caption используется короткий разделитель
  (12 `━` вместо 20), обычный текст сообщения не меняется
  (`order_service.py` + шаблон `detail_card` в `locale.json`)
- Тесты: `tests/test_order_detail_separator.py` — длина разделителя в
  зависимости от типа чека
- Бейдж корзины в главном меню показывал устаревшее количество после
  отправки заказа: `get_user_with_cart` читал устаревшую cart-коллекцию из
  identity map (сессия с `expire_on_commit=False`, без `populate_existing`),
  хотя корзина уже очищена в БД. Теперь `get_user_with_cart` перечитывает
  корзину/заказы из БД (`populate_existing=True` в `get_by_id`); добавлен
  регрессионный тест `test_cart_badge_reset_after_order`

## [0.1.3] - 2026-09-26

### Added

- Уведомление администраторов о новом заказе: при оформлении заказа
  (`checkout_confirm`) каждому админу в фоне (не блокируя ответ клиенту)
  отправляется карточка заказа с кнопкой «📋 Перейти к заказу»
  (callback `admin_order_view:{order_id}`, открывает существующий
  админ-хендлер просмотра заказа). Уведомление на языке каждого админа
  (EN — по умолчанию); ошибка отправки одному админу логируется и не
  блокирует остальных
- Меню команд бота (`/` в чате):
  - `/start` — глобально для всех пользователей (выставляется при старте
    бота)
  - `/admin` — только для администраторов, через per-chat scope
    (`BotCommandScopeChat`); выставляется в `DbSessionMiddleware` с
    in-memory кэшем (повторные API-вызовы не дёргаются; смена языка или
    прав админа — команды переставляются)
- Тесты: `tests/test_new_order_notification.py` (язык админа, кнопка
  заказа, изоляция ошибок, отсутствие заказа) и `tests/test_bot_commands.py`
  (состав команд, per-chat scope, кэш, middleware)

## [0.1.2] - 2026-09-12

### Changed

- Дефолтный язык интерфейса теперь `en` (был `ru`); фолбэк при отсутствии
  перевода всегда на `en`
- Удалена настройка `NOTIFICATIONS_LANG`: уведомления администраторам
  (оплата, отмена) теперь отправляются на языке каждого администратора
  (из БД)
- Новый пользователь создаётся с `language=None`: при первом `/start`
  показывается выбор языка, после выбора язык сохраняется в БД
- Кнопка «Менеджер» в карточке товара настраивается переменной окружения
  `MANAGER_URL`; если не задана — кнопка скрывается (ранее URL был
  захардкожен)

### Fixed

- `IsAdminFilter`: сигнатура `__call__` теперь принимает `admin_ids`
  напрямую (kwarg из workflow data), а не `data: Dict`. aiogram 3 передаёт
  workflow data поимённо и ключ `data` не содержит → на любом сообщении
  (включая клиентские) возникал `TypeError`, т.к. root-фильтр админ-роутера
  проверяется для всех событий. Добавлены регрессионные тесты
  (`tests/test_admin_filter.py`).
- Packaging `shopcrm-core`: `locales/locale.json` теперь включается в wheel
  (`[tool.setuptools.package-data]`). Ранее файл не попадал в установленный
  пакет, из-за чего `Locale` молча падал на пустой словарь и обработчик
  ошибок бота крешил с `FileNotFoundError`

## [0.1.1] - 2026-09-11
